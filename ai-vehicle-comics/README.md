# AI Vehicle Comics

Fictional enterprise AI scenarios, written as industry-wide satire. All people, workflows, events, and figures are illustrative.

A Markdown-first creative workspace for a recurring comic-strip series that explains modern AI, enterprise AI adoption pitfalls, and agentic-AI risks through a compact vehicle analogy.

The series should feel like intelligent workplace/editorial humor: short, dry, visually clear, and professionally sharp. It is not a children's comic, a sci-fi franchise, or an overbuilt fictional world.

## Core Thesis

The AI problem in many enterprises is no longer access to powerful vehicles. It is whether people can drive them, whether the vehicles have enough range, whether the maps are trustworthy, whether the roads are built, whether the route has security guardrails and monitoring, and whether anyone is managing traffic.

## Analogy Framework

| AI Concept | Vehicle Analogy |
|---|---|
| Large language models | Car engines |
| Frontier reasoning models | Powerful V8-class engines |
| Strong general-purpose models | Refined V6-class engines |
| Everyday AI assistants such as ChatGPT, Claude Chat, or Copilot | Regular cars, sedans, practical vehicles |
| Premium Assistant for a business pilot group | Tesla Model Y with autopilot: capable daily-use business vehicle |
| Coding agents such as Codex or Claude Code | Cybertrucks or autonomous work vehicles |
| Token usage / context budget | Fuel, battery charge, energy, and driving range |
| Enterprise data foundations | Trusted maps, navigation data, road signs, and destination information |
| Integrations across enterprise systems | Roads, bridges, access ramps, and open routes |
| AI enablement / literacy | Driver's education and driver's license |
| Human oversight for agents | Ability to take over the wheel |
| Enterprise governance | Traffic rules, road safety, inspections, fleet management |
| Security requirements | Guardrails, median barriers, shoulder lines, and rumble strips |
| PII, secrets, and credentials | Stop signs, no-entry signs, cargo placards, and checkpoints |
| Logging, monitoring, and auditability | Traffic cameras, dashcams, trip logs, road sensors, and control rooms |
| Zero data retention | No vendor parking lot, no overnight storage, cargo leaves with the vehicle |

## Intended Tone

- Witty, concise, and professionally sarcastic.
- Clear enough for technically literate business leaders and enterprise technology professionals.
- Critical of hype, procurement theater, and magical thinking.
- Grounded in real enterprise AI conversations: Copilot adoption, enablement, data foundations, integrations, governance, security requirements, logging and monitoring, vendor AI standards, zero data retention, prompt injection, shadow AI, and agent sprawl.

## Illustrative Pilot Scenario

For a hypothetical enterprise assistant pilot, the working analogy is:

- Premium Assistant: Tesla Model Y with autopilot for daily business use.
- Integrated Assistant: company sedan already connected to Microsoft roads.
- Tokens: fuel, battery charge, energy, and range.
- Data foundations: trusted maps, navigation data, road signs, and destination information.
- Integrations: roads, bridges, ramps, and gated route access.

This distinction matters: a pilot can fail because the users burned the battery, because the map was wrong, or because the route was closed. Those are different comics.

## Security Extension

For security-focused comics, the working analogy is:

- Security requirements: guardrails, median barriers, shoulder lines, and rumble strips.
- PII restrictions: stop signs or no-entry signs labeled "NO PII."
- Secrets and credentials: checkpoint signs labeled "NO SECRETS" or "NO CREDENTIALS."
- Logging and monitoring: traffic cameras, dashcams, trip logs, road sensors, and control rooms.
- Zero data retention: no vendor parking lot, no overnight storage, and no company cargo left behind after the trip.

This distinction matters: security is not one generic red sign. Some controls keep the vehicle on the road, some block restricted cargo, some make the trip observable, and some ensure a vendor route does not retain company data.

## Working Method

1. Start with the message, not the gag.
2. Map the message to the vehicle analogy.
3. Draft a four-panel beat with minimal text.
4. Run the pre-production design check before drawing: confirm the causal chain, visual contrast, panel logic, final consequence, punchline, clutter risk, and overlap watch.
5. Test whether the final panel lands in 3-5 seconds.
6. Tighten labels, dialogue, and punchlines until the idea is sharper, not busier.
7. Use the prompt library to generate visual drafts in the minimalist monochrome editorial style.
8. Record durable creative decisions in `04_decision_log/creative_decisions.md`.
