# Comic 014: Pilot Group Or VIP Parking?

Fictional industry scenario. People, organizations, workflows, and figures are illustrative.

## Status

Fictional enterprise assistant pilot scenario

## Core Message

A pilot group should be selected for learning value and measurable use cases, not for escalation volume or executive proximity.

## Core Critique

Enterprise AI pilots often become access politics. The loudest teams get keys, while the organization fails to select users with clear workflows, measurable outcomes, representative needs, and readiness to share lessons.

## Vehicle Analogy

Premium Assistant licenses are Model Y keys. The pilot group should be a set of test drivers with defined routes, logs, range data, and feedback obligations. It should not be a VIP parking section.

## Candidate Four-Panel Flow

1. A sign reads "Premium Assistant Pilot Selection." A clipboard has criteria: "Use case," "Volume," "Learning value," "Feedback."
2. Leaders replace the clipboard with a velvet rope and sign: "VIP Model Y Parking."
3. Test drivers with real routes wait outside holding maps and trip logs.
4. Inside the VIP section, cars sit unused while someone says, "My leader escalated twice."

## Dialogue And Labels

- Panel 1: Clipboard: "Use case / Metric / Feedback."
- Panel 2: Sign: "VIP Model Y Parking."
- Panel 3: Driver: "We have routes to test."
- Panel 4: VIP user: "My leader escalated twice."

## Punchline Options

- A pilot is an experiment, not a parking perk.
- Escalation is not a use case.
- Pick test drivers, not key collectors.

## Image-Generation Notes

Use the contrast between a testing program and a status perk. Keep the velvet rope simple. The strongest visual is real test drivers holding maps while unused Model Ys sit behind a VIP sign.

## Open Questions

- Should this be sharper about executive escalation, or keep it generalized as "VIP parking"?
- Should pilot criteria include token budget explicitly in panel 1?
