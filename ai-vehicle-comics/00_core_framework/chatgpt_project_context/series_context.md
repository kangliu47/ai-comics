# AI Vehicle Comics: Series Context For ChatGPT

Fictional industry scenario. People, organizations, workflows, and figures are illustrative.

Use this as high-level background context for brainstorming new backlog items.

## Project Identity

AI Vehicle Comics is a concise enterprise AI satire series. It explains modern AI adoption pitfalls, agentic AI risk, security requirements, governance gaps, and pilot rollout mistakes through a compact vehicle and transportation analogy.

It is not a children's comic, a sci-fi franchise, or a glossy product-marketing series. It should feel like intelligent workplace/editorial humor.

## Core Analogy Map

| AI Concept | Vehicle Analogy | Use In Comics |
|---|---|---|
| Large language models | Car engines | Capability source, not the whole experience. |
| Frontier reasoning models | Powerful V8-class engines | Impressive, expensive, often over-discussed. |
| Strong general-purpose models | Refined V6-class engines | Practical and often enough for real work. |
| Everyday assistants | Regular cars or company sedans | Useful today without agentic theatrics. |
| Premium Assistant pilot | Tesla Model Y with autopilot | Capable daily-use business vehicle, still needs route planning and driver judgment. |
| Coding agents | Cybertrucks or autonomous work vehicles | More powerful, specialized, and operationally risky. |
| Tokens/context | Fuel, battery charge, energy, range | Wasteful context loading burns range. |
| Data foundations | Trusted maps, navigation data, road signs | Bad maps make autopilot route badly. |
| Integrations | Roads, bridges, ramps, gated access | Without routes, vehicles cannot reach valuable destinations. |
| Enablement | Driver's education/license | Users need skill before autonomy is useful. |
| Oversight | Taking over the wheel | Autonomy does not remove accountability. |
| Governance | Traffic rules, inspections, fleet management | Scale without chaos. |
| Security requirements | Guardrails, barriers, shoulders, rumble strips | Security is road design, not just final sign-off. |
| Restricted data | Stop signs, checkpoints, cargo labels | Use signs like `NO PII`, `NO SECRETS`, `NO CREDENTIALS`. |
| Logging/monitoring | Traffic cameras, dashcams, trip logs, road sensors | Make AI routes observable and auditable. |
| Zero data retention | No vendor parking lot, no overnight storage | Company data should not remain parked after the trip. |

## Important Distinctions

Do not collapse tokens, data, and integrations:

- Tokens/context are fuel/range.
- Data foundations are maps/navigation.
- Integrations are roads/bridges/ramps.

Do not collapse all security into generic governance:

- Security requirements are guardrails and road design.
- PII/secrets/credentials are restricted cargo or no-entry signs.
- Logging and monitoring are cameras, sensors, and trip logs.
- Zero data retention is no vendor parking lot or no overnight data storage.

These distinctions create sharper comics because each failure mode has a different visual.

## Recurring Visual Devices

Use these devices repeatedly, but sparingly:

- empty classroom for skipped enablement;
- parking garage for licenses without adoption;
- sedans for practical everyday AI;
- Cybertruck/autonomous truck for agentic hype;
- Model Y with autopilot for Premium Assistant pilot use;
- battery/range meter for token usage;
- overloaded trunk/cargo for excessive context;
- bad maps, stale GPS, missing destinations for data problems;
- broken roads, missing bridges, locked gates for integration problems;
- traffic lights, lane markings, dispatch boards for governance;
- guardrails and `NO PII` signs for security requirements;
- traffic cameras and trip logs for monitoring;
- no-parking/no-storage vendor signs for zero data retention;
- forged detour signs for prompt injection.

## Style Constraints

Keep the metaphor compact. Do not create a full fictional universe.

Prefer:

- one clean visual absurdity per panel;
- short signs and labels;
- ordinary corporate settings;
- simple people, slightly more detailed infrastructure;
- punchlines that reveal a structural failure.

Avoid:

- too many labels;
- overloaded dashboards;
- dramatic villains;
- mocking individual workers when the real critique is operating design;
- punchlines that are just slogans.

## Public-content boundary

Use fictional industry scenarios and synthetic figures. Refer to people only by role or approved initials; do not document personal facts, private workplace events, employer/client identities, identity mappings, credentials, or local filesystem paths. Review prompts and artwork as public content.
