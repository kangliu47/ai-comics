# Security Analogy Framework

Use this note when drafting security-aware AI vehicle comics.

The roadside security vocabulary uses guardrails along roads and highways, stop signs for restricted data, logging and monitoring as traffic visibility, and zero data retention as a vendor AI standard. Credit TT on specific artifacts that directly build from this security analogy direction when appropriate.

## Core Security Map

| Security Concept | Vehicle Analogy | Comic Use |
|---|---|---|
| Security requirements | Guardrails, median barriers, lane shoulders, rumble strips | Security is part of the road design, not a binder waved after the crash. |
| PII restrictions | Stop sign or no-entry sign: "NO PII" | Shows a hard data-handling boundary quickly and visually. |
| Secrets and credentials | Stop sign or checkpoint sign: "NO SECRETS" / "NO CREDENTIALS" | Keeps sensitive material from becoming invisible cargo in the vehicle. |
| Data classification | Cargo placards, route permits, checkpoint stickers | Makes the type of data visible before the trip starts. |
| Access control | Badge gates, toll gates, restricted lanes | The vehicle may be capable, but not every route is permitted. |
| Logging and monitoring | Traffic cameras, dashcams, trip logs, road sensors, control room | Shows observability without turning every panel into a dashboard. |
| Auditability | Trip record, inspection log, black box | Proves where the vehicle went and what happened during the trip. |
| Zero data retention | No vendor parking lot, no overnight storage, cargo leaves with the vehicle | Vendor AI standards require the trip to complete without leaving company data parked behind. |
| Data loss prevention | Weigh station, cargo inspection, spill containment | Use when the joke is about preventing sensitive cargo from leaking out of the official route. |
| Approved vendor routes | Marked enterprise highway, approved service station, inspected bridge | Useful for vendor standard comics and procurement/governance humor. |

## Useful Visual Devices

- Roadside guardrails labeled "Security Requirements."
- A clean stop sign reading "NO PII."
- A second stop sign or checkpoint sign reading "NO SECRETS" or "NO CREDENTIALS."
- Road cameras and a small traffic-control room labeled "Monitoring."
- A trip log or black box labeled "Audit Log."
- A vendor rest stop with a sign: "NO OVERNIGHT DATA PARKING."
- A cargo inspection station with boxes labeled "PII," "Secrets," or "Credentials."
- A route permit showing which systems or data classes are allowed on a trip.

## Drafting Rules

- Use one clear security device per panel when possible.
- Make security visible as designed infrastructure, not as a vague warning label.
- Keep signs short: "NO PII" is stronger than a paragraph of policy text.
- Do not make security the villain by default. The better critique is often that the official road was not designed well enough to be safe and usable.
- Distinguish preventive controls, observability, auditability, vendor standards, and data-handling boundaries. They are related but visually different.
- Treat zero data retention as a vendor route rule: the trip may pass through the vendor service, but company data should not remain parked there afterward.

## Example Punchline Patterns

- "The road had guardrails. The demo route did not."
- "No PII means no PII, not 'just for the prototype.'"
- "If there is no trip log, it is not an enterprise route."
- "The vendor promised a highway. Security asked where the parking lot was."
- "Approved route. No overnight data parking."
